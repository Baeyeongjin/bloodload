# 보스 특수패턴과 LibreSprite VFX — 2026-09-09

사용자가 원본 이미지를 복원한 뒤 보스 특수패턴/VFX 수정을 요청했고, 제작 도구로 무료 LibreSprite를 선택했다. 캐릭터·몬스터·배경의 원본 PNG와 `Foe.pixel_motion_pilot = false`는 유지한다.

## 전투 동작

- 예고가 시작되면 공격 중심을 고정한다. 지면 예고, 타격 범위, VFX가 같은 중심과 반경을 사용한다.
- 돌진·점프는 이동하면서 원본 준비 프레임을 진행한다. 도착/착지 순간에 접촉 자세와 피해를 함께 실행하며 준비 동작을 다시 시작하지 않는다.
- 서리 골렘은 별도 두 번째 모션에서 두 번째 피해를 준다. 대기 자세에서 예약 피해만 발생하던 타이머를 사용하지 않는다.
- 낙하체는 0.6초의 전투 시계로 움직인다. 원본 6프레임 구체의 애니메이션 종료가 착탄 전에 피해를 취소하지 않는다.
- 전투 해제·사망은 이동, 복귀, 낙하, 추가 타격을 함께 취소한다. 보스가 뒤로 물러나거나 공중에 있는 동안 전투가 전진 국면으로 바뀌지 않는다.
- 원본 특수 클립 20개의 접촉/시전 프레임을 직접 검토했다. 명확한 칼 궤적이 없는 원본은 발동 자세를 기준으로 VFX를 연결한다.

`FoeTiers.SPECIAL_KIND`의 피해 배수·타수·사거리·예고 시간·3회당 특수 주기는 그대로다. 실제 피해 누락과 동작 타이밍을 수정했으므로 기존 버그가 있던 보스의 체감 난이도는 달라질 수 있다.

## 도트 제작

`tools/AuthorBossVfx.js`는 LibreSprite의 `Image.putPixel`로 RGBA 픽셀을 직접 기록한다. 생성형 이미지 모델이나 기존 캐릭터 재도색은 사용하지 않는다.

- 보스 16종 + 기본 `rock`: 총 17세트, 각 12프레임, 총 204 PNG.
- `assets/anim/boss_vfx/<key>/0.png` … `11.png`.
- 128×64 캔버스, 발원점 (64,48), 원본은 오른쪽으로 전개한다.
- 게임에서는 정수 2배, 최근접 필터, 30fps로 0.4초 재생한다. 프레임마다 크기/기울기를 변형하지 않는다.
- 얇은 바닥 범위 표시는 별도 `boss_floor`가 실제 판정 반경을 표시한다. 효과 그림은 보스별 형태와 색을 보여 준다.
- 편집 원본은 `art/boss_vfx/`에 보관한다. 이 폴더는 실행 PCK에 포함하지 않는다.

LibreSprite 공식 Windows v1.1 포터블을 사용한다. 현재 V8는 실행 파일의 한글 경로에서 초기화에 실패해 실행 파일은 영문 경로의 Codex 작업 폴더에 두었다. 프로젝트 파일은 원래 작업 폴더에 저장한다. 자동 실행에는 격리된 APPDATA/LOCALAPPDATA를 사용한다.

## 검증

- `tests/BossPatternCheck.gd`: 예고 범위, 이동 접촉, 두 번의 서리 모션, 메테오 명중/회피, 취소 등 42건.
- `tests/MonsterMotionCheck.gd`: 원본 278클립의 접촉 자세·프레임 연속성·정지/사망 자세.
- `tests/BossPixelVfxCheck.gd`: 저장 프레임과 실제 Main 재생 경로, 발원점, 속도, 반경, 종료 후 정리.
- 실제 전투 60fps 캡처와 분리된 원본/VFX 비교 렌더를 함께 사용한다.
- `tools/ReleaseSmoke.gd`: 빈 작업 디렉터리에서 최종 PCK를 실행해 원본 57배우의 이동·공격 클립, 새 VFX 17세트, 타이틀·게임·의상·HUD를 확인했다. 내보낸 텍스처는 원본 PNG 파일이 없으므로 `Assets.frames()`가 `ResourceLoader.exists()`를 사용한다.

모든 자동 게임 실행은 두 Windows 앱 데이터 경로를 동일한 새 `build/qa/` 프로필로 격리한다. 사용자 저장 파일은 테스트에 사용하지 않는다.
