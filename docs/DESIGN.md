# Bloodlord — 장기 설계서

> 마지막 업데이트: 2026-08-03

`PLAN.md`가 v1(돌아가는 최소 루프)의 기획이라면 이 문서는 **완성형까지의 설계**다.
v1을 돌려 본 뒤 나온 7가지 요구를 받아서, 서로 어긋나지 않게 하나의 구조로 묶는다.

읽는 순서: **1장(재화)이 전부다.** 2~7장은 1장에 붙는 가지다. 콘텐츠를 먼저 정하고
재화를 나중에 붙이면 반드시 "제일 효율 좋은 하나만 도는" 게임이 된다.

남은 자산 작업은 보스 전용 attack 5종이며, 들어오기 전에는 원본 몹 attack을 쓴다.

## 1. 재화 설계 — 전체를 묶는 뼈대

콘텐츠가 7개면 재화도 나뉘어야 한다. 하나의 재화를 여러 콘텐츠가 주면
플레이어는 **효율 1위 콘텐츠만 돌고 나머지를 안 연다.** 그건 콘텐츠 6개를
버리는 것과 같다.

### 재화 5종

| 재화 | 나오는 곳 | 쓰는 곳 (여기서만) | 오프라인 |
|---|---|---|---|
| **피 (血)** | 잡몹 처치, 방치 보상 | 스탯 3종 업글 | **O** |
| **정수 (精髓)** | 보스 처치, 장비 분해 | 장비 강화 | X |
| **어둠의 보석** | 업적, 일일, 탑 10층, 스테이지 첫 돌파 | 뽑기 3종 | X |
| **탑의 인장** | 마왕의 탑 층 돌파 | 탑 상점 (영구 스탯) | X |
| **하수인 조각** | 펫 뽑기 중복, 일일 시련 | 펫 등급 올리기 | X |

### 이 표가 지키는 두 규칙

**규칙 1 — 오프라인으로 나오는 재화는 피 하나뿐.**
나머지 4종은 전부 손을 대야 나온다. 이게 "켤 이유"다.

**규칙 2 — 그래도 안 켜면 손해가 아니다.**
피만으로도 스탯은 계속 오르고 스테이지는 나아간다. 접속 보상과 방치 보상이
**같은 축을 두고 경쟁하면** 방치형이 아니라 출석 강요 게임이 된다.

두 규칙이 만드는 그림: *안 켜도 앞으로 가고, 켜면 더 빨리 간다.*

### 재화별 성장축 (겹치지 않는다)

```
피      → 공격력 / 공격속도 / 흡혈량      (기본 스탯, 선형)
정수    → 장비 강화                        (장착 중인 3칸을 깊게)
보석    → 뽑기                             (장비·펫 자체를 넓게)
인장    → 탑 상점 영구 스탯                (계정 단위, 리셋 없음)
조각    → 펫 등급                          (펫 하나를 깊게)
```

"깊게(강화)"와 "넓게(뽑기)"를 다른 재화로 나눈 이유: 같은 재화면 항상 한쪽이
정답이라 선택이 사라진다. 다르면 **"이번 주는 장비를 깊게 갈까 넓게 갈까"**가
매번 살아 있는 결정이 된다.

## 2. 전투 연출과 모션 (요청 1)

### 2-0. 영웅은 발렌티노 하나다

**로스터를 늘리지 않는다.** 확장은 캐릭터 추가가 아니라 **스킨**(발렌티노의 다른 외형)이다.

| | 캐릭터 추가 | 스킨 |
|---|---|---|
| 1종당 모션 생성 | idle+walk+attack+hurt+death 5벌 | **0** (같은 모션을 스프라이트만 갈아 재생) |
| 밸런스 | 캐릭터마다 다시 잡아야 함 | 없음 |
| 편성 UI | "누구를 쓸까" 화면 필요 | 없음 |
| 방치형에서의 값 | 낮다 — 자동 전투라 캐릭터 차이가 안 보인다 | 보인다(외형이 곧 값) |

**자동 전투에서 캐릭터를 여러 명 두면 차이가 안 보인다.** 조작이 없으니 개성이
드러날 자리가 없고, 결국 "DPS 제일 높은 애"만 남는다. 반면 스킨은 자동 전투에서도
100% 보인다 — 방치형이 외형을 파는 이유가 그거다.

따라서 **모션은 발렌티노 한 벌만 만들면 끝난다.** 스킨은 그 한 벌을 재생하는
다른 스프라이트 시트일 뿐이다(프레임 수 · 타이밍 동일, 경로만 교체).

```
assets/anim/valentino_1_{idle,walk,attack,hurt,death}/   ← 기준 한 벌
assets/anim/skin_<이름>_{idle,walk,attack,hurt,death}/   ← 스킨도 같은 구성
```

> 코드 쪽 함의: 영웅 모션 경로를 `"res://assets/anim/%s_%s" % [skin, motion]` 로만
> 짜 두면 스킨 추가에 코드 변경이 0이 된다. 지금 하드코딩된 `valentino_1_idle`을
> M1에서 이 형태로 바꾼다.

### 2-1. 모션 상태머신

영웅·몹·보스가 같은 상태머신을 쓴다. 자산이 이미 그 구성(idle/walk/attack)이다.

```
		[등장]
		  │  walk (5~9f, 8fps)
		  ▼
		[전열 도착] ──────────────┐
		  │                      │
		  │  idle (루프)          │ attack (7f, 0.42s) — 공격 주기마다
		  │                      │
		  ▼                      ▼
		[피격] hurt (0.10s 흰 플래시 + 살짝 밀림)
		  │
		  ▼
		[사망] death fx (7f) + 스쿼시 소멸
```

| 상태 | 영웅 | 몹 | 보스 |
|---|---|---|---|
| idle | 1프레임(정지) → **생성함** (5f) | walk 0번 프레임 유용 | walk 0번 프레임 유용 |
| 바라보는 방향 | 원본이 왼쪽 향함 → **`flip_h`로 뒤집어 오른쪽** | 원본 그대로(왼쪽=영웅 쪽) | 원본 그대로 |
| walk | 5f — **전진 구간 상시** | 5~9f — 밀려 들어옴 | 5f — 밀려 들어옴 |
| attack | 7f — **공격 주기에 맞춰 재생** | 7f — **공격 주기에 맞춰 재생** | 없음 → **생성 필요** |
| hurt | **생성함** (5f) + 흰 플래시 | 코드(흰 플래시) | 코드(흰 플래시 + 화면 흔들림) |
| death | **코드** (위로 떠오르며 페이드) + `fx_death_blood` | fx_death_* 7f | fx_explosion + 화면 암전 0.3s |

**중요한 규칙**: 공격 모션 길이가 공격 주기보다 길어지면 모션이 잘린다.
공격 주기는 `attack_interval()`이 `0.60 × 0.9982^(Lv−1)`로 줄어
Lv1000에서 최소 0.10s에 도달한다. 그래서
attack 애니는 **주기에 맞춰 재생 속도를 늘린다** (`fps = 7 / interval`).
빨라질수록 모션이 빨라지는 게 공격속도 업글의 체감이 된다 — 숫자만 오르고
그림이 그대로면 업글한 느낌이 안 난다.

### 2-2. 전진 — 영웅이 몹에게 걸어간다 ✔ 구현됨

**서서 기다리면 몹이 찾아오는 그림은 컨셉과 반대다.** 군주가 사냥터를 넓히는
이야기인데 정작 군주가 안 움직이면 전진감이 없다. 그래서 루프를 뒤집었다.

```
[advance]  배경 시차 스크롤 + 영웅 walk + 무리가 오른쪽에서 밀려 들어옴
	│      선두가 전열(x=300)에 닿으면
	▼
[fight]    다 같이 멈춤 → 영웅 attack 반복
	│      무리 전멸
	▼
[advance]  다음 무리를 부르고 다시 걷는다
```

**한 무리씩 내보낸다.** 예전처럼 0.5~1.1초마다 한 마리씩 흘리면 몹이 끊이지 않아
영웅이 걸을 틈이 없다 — 리듬이 사라진다. 무리 크기는 `2 + 단계/8` (상한 5).

| 값 | 크기 | 이유 |
|---|---|---|
| `Foe.WALK_SPEED` | 120 px/s | 640 → 300 을 약 2.8초에 걷는다. 46이던 원래 값이면 7.4초라 지루하다 |
| `PARALLAX` | 0.5 | 배경은 몹보다 느리게 흘린다 (아래) |
| 전열 도착 판정 | **위치** (`x <= stop_x`) | 시간으로 재면 스폰 위치를 바꿀 때마다 시간도 같이 고쳐야 한다 |

**화면은 세 덩어리다.** ✔ 576 × 896.

| 영역 | y | 내용 |
|---|---|---|
| 상단 상태창 | 0 ~ 160 | 단계 · 피 · 초당 피해 · 진행바 |
| **전투 띠** | 160 ~ 480 | 배경 · 영웅 · 몹. 여기 밖으로는 아무것도 안 나온다 |
| 하단 UI | 480 ~ 896 | 콘텐츠 창 + 탭바 (상시 한 판) |

셋이 화면을 **빈틈없이** 덮는다. 방치형은 화면 대부분이 UI라, 전투 배경이 화면
전체에 깔리면 UI가 그 위에 떠 있는 것처럼 보인다. 액자 안에 가둬야 "게임 화면"과
"조작 화면"이 갈린다.

> 탭에서 "전투"(창 닫기)를 뺀 이유: 레이아웃이 고정이라 창을 닫아도 전투가 안
> 넓어지고 그 자리가 검게 비기만 한다.

**배경 — 가로로 긴 한 장.** ✔ 768 × 160 → 화면에 2배(1536 × 320).

- 세로 320 = 전투 띠 높이라 **딱 맞는다**
- 가로 1536 = 화면 폭의 **2.6배**라 같은 그림이 금방 되돌아오지 않는다
- 바닥 띠가 아래로 쭉 이어져 **발이 닿는 땅**이 생긴다 (예전 세로 배경엔 없었다)
- 좌우 끝에 같은 세로 기둥을 세워 그리게 해서, 이어 붙이면 기둥 둘이 만나 굵은
  기둥 하나로 읽힌다 — **이음매가 그림 안에 숨는다**

**생성 공식·프롬프트·job id는 `BG_RECIPE.md`에 전부 적어 뒀다.**
추가 맵은 그 파일만 보고 같은 규격으로 뽑는다.

**접지** — 영웅·몹 모두 원점이 **발밑**이고 `GROUND_Y = 424`에 맞춘다.
가운데 정렬로 그리면 크기가 다른 몹끼리 발 높이가 어긋나 다 같이 떠 보인다.
발밑에는 납작한 타원 그림자를 깐다 — 접지감의 90%가 이 그림자다.

**시도했다가 버린 것들** (같은 실수를 두 번 하지 않도록):

| 방법 | 왜 버렸나 |
|---|---|
| 288×512 세로 배경 + 좌우 반전 사본 | 픽셀은 이어지지만 대칭 구도라 이음매가 **나비**처럼 보였다 |
| 지나가는 소품 레이어 | 배경이 흐르면 충분한데 화면만 복잡해졌다 |
| 화면 폭으로 스크롤 감기 | 몇 초마다 같은 나무가 지나가 걷는 느낌이 죽는다 |
| `_draw()` 로 배경 뒤 칠하기 | Main은 z=0, 배경 스프라이트는 z=-20 → **배경을 덮어 버린다** |

### 2-2b. 스테이지 전환

스테이지가 넘어가면 그냥 다음 `advance`로 들어간다. 막이 바뀌면 배경만 교체된다.
별도 연출을 안 넣은 이유: 전진이 이미 상시 돌고 있어서 전환용 연출이 따로 필요 없다.

### 2-2c. 기본공격 · 스킬 · 몹 공격 — 어떻게 할 것인가

세 가지를 한 원칙으로 묶는다: **새 모션을 만들지 않는다. 있는 것을 타이밍과
이펙트로 갈라 쓴다.** 발렌티노는 attack 7프레임 한 벌뿐이고, 스킬마다 모션을
뽑으면 스킨 확장(2-0)이 그 수만큼 비싸진다.

#### 기본공격 — 실제 칼끝 기준 접촉

발렌티노 중심은 `HERO_X = 150`이다. 고정 사거리 숫자를 두지 않고 각 모션의
4번째 프레임에서 불투명 픽셀 경계를 읽는다. 현재 측정값은 attack 30px,
heavy 24px이며, 적 중심은 사용 중인 근접 모션 중 가장 짧은 경계에 맞춘다.

| 고칠 것 | 어떻게 |
|---|---|
| 사거리 | `HERO_X + 실제 모션 픽셀 사거리 + 적 너비/2`. 앞 적이 죽으면 후열이 전진한다 |
| 타격 시점 | **7프레임 중 4번째(임팩트)** 에 피해를 적용하고 거리를 다시 검사한다 |
| 타격 위치 | `fx_cleave`(5프레임)를 **맞은 몹 위치**에 띄운다. 영웅 위에 띄우면 겉돈다 |

타격 프레임 동기화가 손맛의 전부다. 모션 시작에 피해를 넣으면 "휘두르기 전에
이미 맞은" 그림이 되고, 그건 아무리 이펙트를 얹어도 안 고쳐진다.

스킬 데이터의 대상 유형은 `melee / area / self`다. `melee`는 자기 모션 이미지를
측정하고, `area`는 도착한 적 무리를 대상으로 하며, `self`는 사거리 검사를 하지 않는다.

#### 스킬 — 모션은 **공격 종류**별로 만든다

스킬마다 모션을 뽑으면 스킬 수만큼 비용이 곱해지고, **스킨(2-0)을 추가할 때마다
그게 통째로 다시 든다.** 반대로 모션이 하나뿐이면 어떤 스킬을 써도 같은 동작이라
스킬을 넣은 티가 안 난다.

그래서 **공격 종류**로 나눈다. 스킬은 종류 중 하나를 골라 쓴다.

| 종류 | 폴더 | 프레임 | 성격 | 생성 |
|---|---|---|---|---|
| `attack` | `valentino_1_attack` | 7 | 베기 — 기본공격 | 기존 |
| `heavy` | `valentino_1_heavy` | 7 | 내려치기 — 크고 느린 한 방 | ✔ 생성 |
| `cast` | `valentino_1_cast` | 7 | 손을 뻗어 시전 — 마법·소환 | ✔ 생성 |

**종류는 3개면 충분하다.** 32px 스프라이트에서 사람이 구분할 수 있는 실루엣 변화가
그 정도다. 더 잘게 나눠도 안 읽히고 스킨 비용만 3배가 된다.

| 스킬 | 쿨 | 종류 | 이펙트(보유) | 규칙 변화 |
|---|---|---|---|---|
| 흡혈 강타 | 8초 | `heavy` | `fx_cleave` | 피해의 20%를 피로 회수 |
| 피의 파도 | 14초 | `heavy` | `fx_explosion` | 전열 **전체** 타격 |
| 망령 소환 | 20초 | `cast` | `fx_death_soul` | 6초간 초당 피해 +30% |
| 피의 장막 | 25초 | `cast` | `fx_holy` | 4초간 받는 피해 −50% |

같은 종류를 쓰는 스킬끼리는 **이펙트로** 갈린다. 종류가 동작을, 이펙트가 정체를 맡는다.

> 스킨을 추가할 때 필요한 것은 `{skin}_{idle,walk,attack,heavy,cast,hurt}` 6벌뿐이다.
> 스킬을 20개로 늘려도 이 숫자는 안 변한다.

#### 몹 공격 — 22종 × 7프레임이 놀고 있다

전열에 도착한 몹은 자기 주기로 `attack`을 재생하고 영웅 HP를 깎는다(2-3).

| 항목 | 값 |
|---|---|
| 공격 주기 | `1.2 + hp_mult × 0.3` 초 — 단단한 놈일수록 느리게 친다 |
| 피해 | `enemy_power(stage) × 4` |
| 타격 프레임 | 7프레임 중 4번째 |
| 피격 표시 | 영웅 `hurt` 모션(5프레임, 생성 완료) + 흰 플래시 |

주기를 `hp_mult`에서 뽑는 이유: 몹마다 공격 주기 표를 새로 만들 필요가 없다.
이미 있는 값 하나로 "단단한 놈은 느리고 무겁다"가 자동으로 나온다.

### 2-3. 영웅에게 HP를 준다 — 이 설계의 분기점

**M1 구현 완료: 영웅 HP·회복·피격·사망·3초 부활과 오프라인 생존 판정이 연결됐다.**

죽어서 막히는 벽이 성장 신호가 되고, 이후 뽑기·업적·탑의 필요성을 만든다.

| 항목 | 설계 |
|---|---|
| 영웅 HP | `100 × (1 + 0.02 × (체력Lv−1) + 0.12 × 방어구 실효 강화치)` |
| 몹 공격 | 전열 도착 후 자기 주기마다 `enemy_power(stage) × 4` |
| 회복 | 최대 체력 × `0.015 × (체력회복Lv−1)` /초 |
| 사망 | 3초 부활, **그 스테이지 처치 수 0으로** (스테이지 자체는 안 내려감) |
| 벽의 의미 | "죽어서 못 넘음" = 성장 신호. 게임이 플레이어에게 말하는 유일한 말 |

**오프라인 계산은 그대로 결정론적으로 유지된다.** 난수를 안 쓰기 때문이다:

```
스테이지 클리어 가능한가?
  영웅이 버티는 시간 = HP / (전열 몹 수 × 몹 DPS)
  스테이지 밀어내는 시간 = 필요 처치수 × 몹 체력 / 영웅 DPS
  → 밀어내는 시간 < 버티는 시간 이면 클리어
```

오프라인 진행은 **클리어 가능한 최고 스테이지까지만** 올라가고 거기서 멈춰
피만 모은다. 켜 보면 "여기서 막혔다"가 보이고, 그게 접속했을 때 할 일이 된다.

> 이건 v1의 "영웅 불사" 전제를 뒤집는 변경이다. 뒤집는 이유는 위에 적은
> 하나뿐이다 — **벽이 없으면 나머지 6개 요청이 전부 무의미해진다.**

## 3. 스테이지와 보스 (요청 2)

### 3-1. 구조

| 층위 | 수 | 내용 |
|---|---|---|
| 큰 단계 | 100 | 화면 표기 `1`~`100` |
| 세부 구간 | 단계마다 10 | 1~4 잡몹, **5 중간보스**, 6~9 잡몹, **10 보스** |
| 총 | 1,000구간 | `1-1`부터 `100-10`까지 |
| 테마 | 5 | 큰 단계마다 기존 배경·몬스터·보스를 순환 재사용 |

새 배경을 먼저 늘리지 않고 기존 5개 테마를 순환해 진행 구조와 밸런스를 검증한다.

### 3-2. 중간보스 (각 큰 단계의 5번째 구간)

잡몹 하나를 승격시킨다. 새 자산이 필요 없다.

```
체력 ×3.5 · 일반몹 대비 크기 ×1.5 · 이름 접두어 "타락한/굶주린/피에 젖은"
등장 시 화면 살짝 흔들림 + 이름 배너 1.2초
```

### 3-3. 보스 (각 큰 단계의 10번째 구간)

`boss_1~5_walk`를 막별 보스에 연결한다.

| 막 | 보스 | 자산 |
|---|---|---|
| 1 깨어난 무덤 | 망령 기사 | `boss_1_walk` |
| 2 화형의 언덕 | 가고일 군주 | `boss_2_walk` |
| 3 서리 봉인지 | 프로스트 골렘 | `boss_3_walk` |
| 4 핏빛 성소 | 눈알 덩어리 | `boss_4_walk` |
| 5 빼앗긴 본성 | 다크 나이트 | `boss_5_walk` |
| 이후 큰 단계 | 위 5개 테마와 보스를 순환 | 기존 자산 재사용 |

> 보스 전용 공격 자산이 생기기 전까지는 해당 보스의 원본 몹 `{key}_attack`을 임시 사용한다.
> 전용 자산이 들어오면 경로만 바꾸고 공격 타이밍(7프레임 중 4번째)은 유지한다.

**보스전 규칙**
- 제한시간 **60초**. 못 죽이면 실패 → 재도전(패널티 없음).
- 제한시간이 있는 이유: 보스는 DPS 검문소다. 시간이 없으면 결국 다 통과라
  검문의 뜻이 없다.
- 보스 등장 시 잡몹 스폰 정지 (v1과 동일).
- 처치 보상: **정수** + 어둠의 보석 (첫 클리어만) + 확정 장비 드랍.

## 4. 뽑기 3종과 해금 (요청 3)

### 4-1. 3종과 해금 시점

| 뽑기 | 해금 | 풀 크기 | 재화 | 1회 |
|---|---|---|---|---|
| **무기 뽑기** | 처음부터 | 24종 | 어둠의 보석 | 30 |
| **방어구 뽑기** | 스테이지 **10** 도달 | 24종 (10 보유 + **14 생성 필요**) | 어둠의 보석 | 30 |
| **하수인(펫) 뽑기** | 스테이지 **25** 도달 | 11종 (**생성 0** — 아래) | 어둠의 보석 | 50 |

해금을 스테이지에 묶는 이유: 콘텐츠를 한 번에 다 열면 플레이어가 첫날 전부
훑고 "다 봤다"가 된다. 나눠서 열면 **25단계에 도달하는 것 자체가 목표**가 된다.

### 4-2. 펫은 새로 안 그린다

**보유 캐릭터 10명(발렌티노 제외)을 하수인으로 전용한다.**
walk 5~9프레임 + attack 7프레임이 전부 이미 있다. 생성 비용 0.

**2-0의 "영웅은 하나"와 어긋나지 않는다.** 그 10명은 플레이어가 조종하는 영웅이
아니라 군주가 부리는 종복이다 — 고를 수는 있지만 **밸런스 축이 아니라 수집 축**이다.
arrow-rpg에서 동료였던 캐릭터들이 여기선 피의 종복이 된 것이고, 그게 이 게임의 톤이다.

**펫은 실제로 싸운다.** 영웅 뒤에 서서 자기 주기로 공격한다(영웅 DPS의 25%).
장식이면 뽑을 이유가 약하지만 화면에서 같이 때리면 뽑은 게 눈에 보인다.
최대 2마리 편성 — 3마리 넘으면 세로 화면에서 영웅이 안 보인다.

| 펫 등급 | 조각 | 피해 배수 |
|---|---|---|
| 1성 (뽑은 직후) | — | 0.25 |
| 2성 | 20 | 0.35 |
| 3성 | 60 | 0.50 |
| 4성 | 150 | 0.70 |
| 5성 | 300 | 1.00 |

### 4-2b. 무기는 뽑고 끝이 아니라 **키운다**

무기를 뽑기만 하면 새 무기가 나온 순간 옛 무기가 쓰레기가 된다. 그러면 뽑기가
"교체"가 되고, 교체는 한 번 좋은 게 나오면 그다음부터 지루하다.

**장비마다 자기 레벨을 둔다.** 뽑은 장비는 보관함에 남고, 중복으로 나오면 그 장비의
재료가 된다. 키운 장비는 등급이 낮아도 값이 있다 — 그게 "이 장비를 키울까"라는
결정을 만든다.

| 항목 | 설계 |
|---|---|
| 보관 | 뽑은 무기·방어구·장신구는 전부 보관함에 남는다 (슬롯별 장착 1개) |
| 레벨 | 장비마다 `Lv`. 실효 수치 = `base × (1 + 0.25 × Lv)` |
| 재료 | **중복 뽑기**가 같은 장비의 조각이 된다 (꽝이 없다) |
| 표시 | 4열 큰 격자에 장비 그림 + `Lv.N` + 조각 수 + 등급 틀 + 장착 표시 |
| 보유 효과 | 장착 여부와 무관하게 고유 장비마다 해당 스탯 +0.5/1/2/4/8% |
| 승급 | 같은 장비 조각 5개 → 한 등급 위로. 등급이 오르면 `base` 가 바뀐다 |

> 전투 드랍은 기존 "더 센 장비 자동 교체 + 약한 장비 정수 분해"를 유지한다.
> 장비 소환 결과는 전부 보관함에 넣고 수동 장착한다. 뽑기가 붙는 순간부터는
> "뭘 키울까"가 결정이므로 소환 장비까지 자동 교체하면 안 된다.

### 4-3. 확률과 천장

장비와 스킬이 같은 5등급·확률·천장 코어를 쓴다. `GearDefs.RARITY`는 M3에서
고급 등급을 추가해 아래 표로 마이그레이션한다.

| 등급 | 일반 | 고급 | 희귀 | 영웅 | 전설 |
|---|---:|---:|---:|---:|---:|
| 공개 확률 | 50% | 30% | 14% | 5% | 1% |

| 장치 | 값 | 왜 |
|---|---|---|
| 10연 | 희귀 이상 **1개 확정** + 등급별 연출 | 10연이 항상 꽝이면 뽑기를 안 돌린다 |
| 천장 | **100연** 내 전설 확정 | 확률만 있으면 운 나쁜 사람이 게임을 접는다. 100~200이 한국 시장 표준이라 하단을 잡았다 |
| 중복 | 해당 장비/스킬 **조각으로 전환** | 조각으로 승급·돌파해 모든 뽑기가 전진한다 |
| 마일리지 | 1회당 1, 교환소에서 원하는 조각 구매 | 최대 돌파 뒤 중복도 쓸 곳이 남는다 |

천장 카운터는 뽑기별로 따로 센다(무기에서 쌓은 걸 펫에 못 쓴다).

### 4-4. 장비·스킬 뽑기는 같이 구현한다

M3에서 공용 `1회/10연·확률 공개·천장·조각·마일리지` 코어를 먼저 만들고
**장비 탭과 스킬 탭을 같은 마일스톤에 연다.** 장비는 같은 장비 조각으로 합성·승급하고,
스킬은 같은 스킬 조각으로 돌파한다. 현재 자동 스킬 3종은 기본 지급 스킬로 남겨
뽑기 전에도 전투가 돌아가게 하고, 뽑은 스킬 중 최대 3개를 자동 우선순위에 장착한다.

무료 수급은 일일·업적·첫 돌파 보석과 일일 무료 1회로 둔다. 오프라인 보석 지급은
"오프라인 재화는 피만" 원칙과 충돌하므로 넣지 않고, 벽 구간의 첫 돌파 보상량으로 조정한다.

## 5. 업적 (요청 4)

### 5-1. 5계열 × 8단계 = 40개

| 계열 | 지표 | 1단계 → 8단계 |
|---|---|---|
| 사냥 | 누적 처치 | 100 → 500,000 |
| 정복 | 최고 스테이지 | 5 → 100 |
| 단련 | 장비 강화 총 레벨 | 10 → 1,000 |
| 수집 | 뽑기 누적 횟수 | 10 → 2,000 |
| 등반 | 마왕의 탑 최고 층 | 5 → 200 |

**보상 = 어둠의 보석 + 영구 스탯 +1%** (계열별로 다른 스탯).
업적이 보석의 주 공급원이다 — 그래야 "그냥 하다 보면 뽑기가 돈다".

### 5-2. 업적 지표는 이미 세고 있는 것만 쓴다

`kills` · `stage` · 장비 `lv` 합 · 뽑기 횟수 · 탑 층 — 새로 추적할 게 없다.
**세지 않는 지표로 업적을 만들지 않는다.** 업적 때문에 카운터를 새로 다는 순간
저장 스키마가 업적 수만큼 늘어난다.

### 5-3. 알림

달성 시 상단 배너 1회(오프라인 배너와 같은 자리 재사용) + 탭바 업적 아이콘에 붉은 점.
붉은 점은 **받지 않은 보상이 있을 때만**. 항상 켜져 있으면 아무 뜻이 없다.

## 6. 일일 도전 (요청 5)

### 6-1. 3종 × 3회/일

| 도전 | 주는 재화 | 소요 | 왜 이 재화 |
|---|---|---|---|
| **피의 만찬** | 피 (현재 스테이지 30분치) | 30초 | 방치 보상 압축 = 켠 값 |
| **사냥터** | 정수 | 30초 | 장비 강화 속도를 접속에 묶는다 |
| **시련** | 어둠의 보석 + 하수인 조각 | 30초 | 뽑기 속도를 접속에 묶는다 |

**3회 제한인 이유**: 무제한이면 최적 플레이가 "계속 도는 것"이 되고,
그건 방치형이 아니라 노동이다. 3회는 하루 2~3분이다.

**실패가 없다.** 일일은 벽이 아니라 수도꼭지다. 벽은 본편과 탑에만 둔다.
보상은 `현재 최고 스테이지`에 비례하므로 본편 진행이 곧 일일 효율이 된다.

### 6-2. 리셋

```
매일 04:00 (Time.get_datetime_dict_from_system 기준)
- 04:00 인 이유: 자정 리셋은 자정 직전에 켠 사람에게 하루를 두 번 준다.
- 저장에는 "마지막 리셋 날짜"만 둔다. 접속 시 날짜가 바뀌었으면 횟수 복구.
- 미사용 횟수는 이월하지 않는다. 이월하면 일주일 뒤 21회가 쌓여 다시 노동이 된다.
```

## 7. 마왕의 탑 (요청 6)

### 7-1. 구조

| 항목 | 값 |
|---|---|
| 층 | 무한 (실질 상한은 성장이 정한다) |
| 층당 | 몹 1마리 (막 로스터에서 순환, 10층마다 보스) |
| 제한시간 | **30초** |
| 실패 | 그 층에서 멈춤. 재도전 무제한 (**입장권 없음**) |
| 오프라인 | **없음** |
| 층 체력 | `12 × 1.13^층` — 본편(1.045)보다 훨씬 가파르다 |

**입장권을 안 두는 이유**: 입장권은 "오늘 3번 실패했으니 내일 오세요"다.
그건 벽이 아니라 대기다. 탑의 벽은 **DPS**여야 한다. 몇 번을 도전하든
DPS가 모자라면 못 넘고, 넘는 방법은 성장뿐이다 — 그게 탑의 존재 이유다.

### 7-2. 본편과 뭐가 다른가

| | 본편 | 마왕의 탑 |
|---|---|---|
| 성장축 | 넓게 (여러 스탯) | **순수 DPS 검문** |
| 오프라인 | O | X |
| 진행 | 되돌아가지 않음 | 최고 층 기록만 남음 |
| 재화 | 피 | 인장 |

본편은 **얼마나 오래 방치했나**를 재고, 탑은 **얼마나 잘 키웠나**를 잰다.
같은 성장을 두 각도로 재기 때문에 둘 다 볼 이유가 생긴다.

### 7-3. 탑 상점

인장으로만 산다. 전부 **영구**(환생이 생겨도 안 사라진다).

[run]      stage, best_stage, kills, play_time
[wallet]   blood, essence, gem, seal, shard
[up]       damage, speed, gold
[gear]     equipped = {slot:item}, inventory = {icon:item+copies}

## 13. 코어 시스템 점검표 — 방치형이 죽는 5가지 지점

업계에서 반복 검증된 5개 축이다. **우리 설계를 여기 대고 정직하게 채점한다.**
맞춘 곳보다 **어긋난 곳이 중요하다** — 어긋났다면 이유가 있어야 하고, 이유가
없으면 그건 그냥 구멍이다.

| # | 축 | 우리 상태 | 판정 |
|---|---|---|---|
| 1 | 성장 곡선 | 초반 폭발 → 중반 해금 → 후반 누적 | ⚠ **미검증** |
| 2 | 오프라인 보상 | 효율 50% · 8시간 캡 · 결정론 계산 | ✅ / ⚠ 서버 없음 |
| 3 | 자동전투 | 완전 자동, 개입 지점 = 재화 배분 | ⚠ **가장 위험** |
| 4 | 가챠·수집 | 3종 뽑기 · 천장 100 · 중복→조각 | ✅ (도감 보상 2026-08-04 구현) |
| 5 | 일일 콘텐츠 | 3종 × 3회 · 04:00 리셋 | ✅ / ❌ 연속 접속 없음 |

### 1. 성장 곡선 — 미검증

"초반 1시간은 5분마다 큰 변화"가 기준인데, **우리는 아직 재 본 적이 없다.**
8-2의 목표 표(첫 10분 12단계 / 첫날 28단계)가 그 대용이지만 **5분 단위로는 안 쟀다.**

> **할 일**: 첫 1시간을 5분 구간으로 쪼개 "이 구간에 무엇이 열리는가"를 채운다.
> 빈 구간이 있으면 거기서 이탈한다.

**재화 종류가 많다는 경고에 걸린다.** 우리는 5종(피·정수·보석·인장·조각)이다.
1장의 논리(콘텐츠마다 고유 재화)는 여전히 옳지만, **처음부터 5개를 다 보여주면 안 된다.**

| 시점 | 보이는 재화 |
|---|---|
| v1 | 피 (1종) |
| M2 | + 정수 (2종) |
| M3 | + 보석 · 조각 (4종) |
| M5 | + 인장 (5종) |

재화도 스탯처럼 **해금**한다. 첫 화면에 5개가 있으면 뭐가 중요한지 모른다.

### 2. 오프라인 보상 — 서버가 없다 (알려진 천장)

계산은 서버에서 해야 치팅을 막는다는 게 정석이다. **우리는 서버가 없다.**

지금은 맞는 선택이다 — 싱글 플레이에 결제도 랭킹도 없어서 치팅해도 자기 저장만
망가진다. 서버를 붙이면 이 프로젝트는 다른 프로젝트가 된다(12장).

> **천장이 드러나는 조건**: 결제 · 랭킹 · 길드 중 **하나라도** 붙는 순간
> 오프라인 계산은 서버로 옮겨야 한다. 그래서 `_grant_offline()` 은 지금도
> **순수 함수**로 유지한다 — 서버로 옮길 때 그대로 들어내면 되게.

광고 2배 보상은 검증된 패턴이라 자리를 비워 둔다(12장에서 결제·광고는 설계 후로 미룸).

### 3. 자동전투 — 여기가 제일 위험하다

**"자동전투가 진짜로 자동이면 며칠 만에 이탈한다"** — 우리 설계가 정확히 여기 있다.
12장에서 수동 스킬을 뺐고, 개입 지점은 재화 배분 하나뿐이다.

그 선택 자체는 유지한다(조작을 넣으면 방치가 아니다). 대신 **개입할 곳을 하나 만든다**:

| 콘텐츠 | 개입 |
|---|---|
| 본편 | 없음 (완전 자동 — 방치의 정의) |
| **마왕의 탑** | **수동 스킬 발동 가능**. 30초 제한이라 언제 쓰느냐가 결과를 바꾼다 |
| 보스전 | 60초 제한. 스킬 수동 발동으로 클리어 여부가 갈릴 수 있게 |

**본편은 자동, 검문소는 수동.** 이러면 "자동전투는 기본, 수동은 보너스"가 성립하고
방치의 약속도 안 깨진다 — 안 눌러도 언젠가는 넘고, 누르면 지금 넘는다.

> D+7 리텐션이 무너지면 **여기부터 손댄다.** 콘텐츠를 더 붙이는 게 아니라
> 개입 지점을 넓히는 쪽이다.

### 4. 가챠·수집 — 컬렉션 보상이 없었다

도감이 처치 수만 세고 **보상이 없었다.** "모아도 보상이 없으면 동기가 없다"에
그대로 걸린다. 고친다:

기준은 **발견 종 수가 아니라 지식 합계**다(2026-08-04 변경). 종 수로 하면 한 마리씩
22번 만나면 끝이라 목표가 며칠 만에 닫힌다. 지식 합계는 방치로 계속 오른다.

- 몹별 **지식 레벨** = 처치 10 / 100 / 500 / 2000 / 10000 을 넘을 때마다 1 (최대 5)
- 지식 레벨당 **그 몹 상대 피해 +4%**
- **지식 합계** = 22종의 레벨 총합 (최대 110)

| 지식 합계 | 보상 (영구) |
|---|---|
| 3 | 공격력 +2% |
| 10 | 흡혈량 +3% |
| 22 (모든 몹 1레벨) | 공격력 +5% |
| 44 (모든 몹 2레벨) | 체력 +8% |
| 66 | 흡혈량 +10% |
| 88 | 공격력 +12% |
| 110 (만렙) | 공격력 +15% + 보석 300 |

**영구적이고 의미 있는 능력치**여야 한다. 소모품을 주면 그때뿐이다.
도감 탭의 **능력치** 버튼이 이 표를 받은 것/남은 것으로 펼쳐 보여 준다.

신규 캐릭터 주기(2~4주)는 우리에게 **스킨 주기**로 번역된다(2-0). 로스터를
안 늘리므로 기존 유저의 노력이 무의미해지는 일도 없다 — 스킨은 성능이 아니다.

### 5. 일일 콘텐츠 — 연속 접속이 없었다

3종 × 3회는 기준에 맞다(3가지 미만). **빠진 건 연속 접속과 복귀다.**

| 장치 | 설계 |
|---|---|
| 연속 접속 | 7일 주기. 7일차에 큰 보상(전설 확정권) |
| 끊겨도 | **누적 일수는 안 깎는다.** 연속만 초기화 |
