# 스탯 개편 — 15분할 (사장님 확정 2026-08-20)

사장님 요구 넷:
1. 스탯을 훨씬 많은 레벨까지 올릴 수 있게
2. 훈련 비용 대폭 너프
3. 흡혈량 삭제 — "공격력이 아니다"
4. 혈액은 재화 던전 + 방치로만

사장님 결정(2026-08-20): **숫자만 커진다(곡선 보존)** · **15배 분할**.

## 0. 조사에서 확정된 사실 — 왜 이 방향인가

**진짜 병목은 상한이 아니라 비용 지수다.** 90일차 상한은 762인데 실제 구매는
181레벨 — 상한이 이미 4배 놀고 있다. 지수 곡선에서 도달 레벨은 `ln(예산)/ln(지수)`
라, 1.15로는 혈액 1e12를 부어도 168레벨이 끝이다. 참고작 Lv.20,000을 지금 식으로
사려면 누적 7.19e183 혈액이 필요하다.

**업계도 같다**: 레벨이 수천을 넘는 게임은 예외 없이 비용이 지수가 아니다
(NGU Idle 10억 레벨=선형, Clicker Heroes Ancients=선형). 그리고 **합연산 스탯만**
수만 레벨을 주고 %·곱연산(공속·치확·회복)은 100~1,000에서 하드캡한다 — 참고작
화면의 "20,000 vs 100" 4단 상한이 그 규칙이다. 우리 공격력은 이미 합연산
(DMG_PER_LEVEL 0.035)이라 조건을 만족한다.

**그래서 곡선을 새로 만들지 않고 눈금을 잘게 나눈다.** 1레벨을 15조각으로 쪼개면
같은 자리의 누적 비용이 수학적으로 **항등**이라 곡선이 안 깨지는데, 화면 숫자는
15배가 되고 버튼 가격은 1/16이 된다.

## 1. 비용 — Balance.upgrade_cost 한 함수만

```gdscript
const SPLIT := 15          # 옛 1레벨 = 새 15레벨
const COST_SCALE := 1.0    # 곡선 완전 보존(사장님 결정). 낮추면 실제로 빨라진다

static func upgrade_cost(level: int, base := UP_BASE, e := UP_EXP) -> float:
	var r := pow(e, 1.0 / float(SPLIT))
	return base * (r - 1.0) / (e - 1.0) * COST_SCALE * pow(r, float(level - 1))
```

**항등 증명**: 옛 누적 `b(e^(N-1)-1)/(e-1)`, 새 누적 `b'(r^(M-1)-1)/(r-1)`,
`r = e^(1/15)`, `M = 1+15(N-1)` → `r^(M-1) = e^(N-1)`. 두 식이 같아지는 유일한
`b' = b(r-1)/(e-1)`. 등가 레벨에서 누적 비용 오차 **0.0000%**.

**버튼 가격 배율은 지수마다 다르다**(검증 지적 — 하나로 뭉개면 안 된다):

| 지수 | 스탯 | 가격 배율 |
|---|---|---|
| 1.15 | 공격력·체력 | 1/16.03 |
| 1.22 | 공속·회복 | 1/16.49 |
| 1.28 | 치명피해 | 1/16.87 |
| 1.35 | 치확 | 1/17.32 |

StatDefs 표의 base/exp 숫자는 **손대지 않는다**.

**묶음·MAX는 닫힌식으로**(현행 O(n) 루프는 Lv 수천에서 못 버틴다):

```gdscript
static func buy_cost(level: int, n: int, base := UP_BASE, e := UP_EXP) -> float:
	var r := pow(e, 1.0 / float(SPLIT))
	return upgrade_cost(level, base, e) * (pow(r, float(n)) - 1.0) / (r - 1.0)

static func max_steps(level: int, gold: float, base := UP_BASE, e := UP_EXP) -> int:
	var r := pow(e, 1.0 / float(SPLIT))
	return int(floor(log(1.0 + maxf(0.0, gold) * (r - 1.0) * 0.999999
		/ upgrade_cost(level, base, e)) / log(r)))
```

## 2. 효과 — 상수를 하나도 안 바꾼다

경계에서 한 번만 나눈다. `DMG_PER_LEVEL 0.035` 등 여섯 상수가 그대로 남으므로
**docs/STATS.md 6장("효과는 만지지 않는다")을 안 깬다.**

```gdscript
# Main.gd  int -> float
func _stat_eff(key: String) -> float:
	return 1.0 + float(stat_lv(key) - 1) / float(Balance.SPLIT) \
		+ float(TitleDefs.bonus(key, titles_got))
```

Balance의 hero_damage / hero_max_hp / hero_regen_per_sec / attack_interval /
crit_mult 다섯 함수의 레벨 인자를 int→float으로만 바꾼다(maxi→maxf).
칭호 무료 레벨은 **옛 단위 그대로** 둬서 TitleDefs 106행을 안 건드린다.

## 3. 상한 — 공식 유지, 계수만 ×15

```gdscript
const CAP_BASE := 900        # 60 → 1+15×59 = 886, 900으로 반올림
const CAP_PER_FLOOR := 150   # 10 × 15
const CAP_PER_STAGE := 37.5  # 2.5 × 15
```

`train_cap = 900 + max(150 × 미궁층, int(37.5 × (구간-1)))` — **"미궁 층 OR 본편
구간 중 큰 쪽"의 OR 구조 유지**(90일차 상한 336 교착의 해법이었던 자리).

| 상황 | 상한 |
|---|---|
| 시작 | 900 |
| 30일 (10층/170구간) | 7,237 |
| 90일 (46층/282구간) | 11,437 |
| 만렙 (100층/500구간) | 19,612 |

**스탯별 4단 상한이 자동으로 나온다** — 참고작 구조와 같다:
19,612(공격력·체력·치피) / 14,919(공속) / 1,486(치확) / 751(회복).
공속 바닥은 14,919다(0.6×0.9982^994.53 = 0.10, 검증 정정).

**선행값도 같은 규칙** `1 + 15×(옛-1)`: damage 5→61, tough 5→61, speed 10→136,
tough 15→211, crit 5→61. ×15가 아니라 **+1 규칙**을 써야 문턱이 안 밀린다.

**REGEN_CAP_LEVEL은 51(유효 단위)로 두고** StatDefs 쪽에서
`1 + Balance.SPLIT * (Balance.REGEN_CAP_LEVEL - 1)`로 쓴다 — 상수를 751로 바꾸면
BalanceTest의 회복 상한 검사가 깨진다(검증 지적).

## 4. 흡혈량 삭제 — 아무것도 안 죽는다

스탯 키 "gold"가 실제 효과를 내는 자리는 **딱 한 줄**이지만, 칭호 21종(무료
125레벨)·장신구 슬롯·유물 2·혈맥 3·펫 5·도감·수집·은총이 같은 키를 본다.
그냥 지우면 훈련 한 번 안 한 유저도 혈액이 31~64% 증발한다.

**해법**: `gold_mult()`의 첫 항만 칭호 참조로 바꾼다.

```gdscript
# Main.gd:568
return (1.0 + 0.15 * float(TitleDefs.bonus("gold", titles_got))
	+ _gear_stat("gold") * 0.02) * ...   # 나머지 인자 그대로
```

StatDefs.STATS에서 `gold` 한 줄 제거(7종→6종). 장신구·유물·혈맥·펫·도감·은총은
StatDefs를 안 거치므로 **전부 무손상**. TitleDefs 106행 무수정.
`TITLE_STAT_ICON["gold"]`는 **반드시 남긴다** — 직접 인덱싱이라 지우면 크래시.

## 5. 혈액 = 던전 + 방치

```gdscript
const IDLE_EFF := 5.0 / 9.0   # 하루 총량 보존: 8h×0.5+1h×1.0 = 9h×(5/9)

func blood_per_sec() -> float:
	var kill_time := maxf(0.2, float(_offline_profile(stage)["hp"]) / maxf(0.001, dps()))
	return StageDefs.gold_per_kill(stage) * gold_mult() / kill_time * IDLE_EFF
```

- 처치 혈액 0 (`f.setup(..., 0.0, boss)`)
- 접속 중 1초 틱에 `gold += blood_per_sec()`
- 오프라인은 기존 식을 이 함수로 교체(코드가 줄어든다)
- 스킬 흡혈(`gold += dealt * 0.20`) 삭제 — 처치 혈액의 0.02~0.6%
- 재화 던전은 손대지 않는다(이미 gold_mult를 안 타는 독립 수도꼭지)

**검증 경고(반드시 기록)**: PaceProbe가 "수급 변동 0"으로 보이는 것은 시뮬과 새
식이 같은 느슨한 모델(`hp/dps`)을 쓰기 때문이지 실기가 같아서가 아니다. 실제
접속 수입은 초반에 최대 2.6배가 될 수 있다(Balance.push_seconds 주석 1-1: 모델
0.212초 vs 실측 0.73초). **적용 후 PaceProbe 1회 재측정이 필요하다.**

## 6. 마이그레이션 — 가장 위험한 한 줄

```gdscript
# _load_game(), lv 읽은 직후
if not cfg.has_section_key("up", "split15"):
	var g := maxi(1, int(lv.get("gold", 1)))
	# 환급은 **새 레벨 단위**로 넘긴다. COST_SCALE 은 upgrade_cost 안에 이미 있다
	gold += Balance.buy_cost(1, Balance.SPLIT * (g - 1), 14.0, 1.16)
	lv.erase("gold")
	for k in lv:
		lv[k] = 1 + Balance.SPLIT * (int(lv[k]) - 1)
	for k in lv.keys():
		if StatDefs.of(str(k)).is_empty():
			lv.erase(k)
```

검증이 잡은 오류: 옛 안은 `buy_cost(1, g-1, ...) * 0.5`였는데 (a) n에 옛 단위를
넣었고 (b) COST_SCALE을 두 번 곱해서 **290만 배 부족**했다(Lv100 기준 정답
1.054e8 vs 36.7). 크래시가 안 나서 QA에서 안 잡힌다.

분할을 두 번 돌리면 레벨이 225배, 안 돌리면 전투력이 1/15로 붕괴한다 —
`split15` 플래그가 유일한 방어선이다.

## 7. 화면

**이미 있는 것**: x1/x10/x100(등비합 정확) · "레벨 N / 상한" · 효과 한 줄 ·
잠긴 줄 회색 조건 · 만렙 회색 · 승급 배지. 참고작과 구조가 이미 같다.

**고칠 것**
1. **MAX 버튼** — `BUY_STEPS := [1, 10, 100, -1]`. `_step_for`에서 -1이면
   `clampi(Balance.max_steps(...), 0, cap - lv)`. **음수가 그대로 흐르면 혈액이
   늘고 레벨이 준다**(검증이 찾은 취약점) — 0이면 버튼 비활성.
2. **배수 저장** — 지금은 켤 때마다 x1로 돌아간다.
3. **가격 식 일원화** — 표시(raw exp)와 시뮬(cost_exp)이 갈려 있던 위험을 여기서
   같이 없앤다. 올림은 **낱개에만** 건다(묶음에 걸면 x100이 낱개보다 싸진다).
4. **효과 칸 누적 표기** — 레벨당 +0.0327 피해라 30레벨을 눌러야 정수가 1 오른다.
   "+188.8k 피해" 대신 "+2,700 (×94.5)" 식으로 누적을 같이 적어야 사장님 요구가
   성립한다(참고작의 "+2,979" 자리).
5. 흡혈량 특례 알림 삭제 · 펫 상세 이름은 `TitleDefs.stat_name` 사용.
6. 칭호 공짜 레벨 표시에 `× Balance.SPLIT`(단위 일치).
7. `GoalDefs` damage_lv 트랙 base 10 → 150.

## 8. 테스트 — 검증이 잡은 파손 목록

- **BalanceTest 숫자는 손대지 않는다**(주석만 수정) — `_build_dps`가
  `Balance.hero_damage`를 직접 부르므로 이미 유효 단위다. 숫자를 15배 하면
  assert가 깨진다.

## 10. 남는 것 (이번에 안 하는 것)

- **참고작의 ◇각성 축** — 레벨당 증가량 자체를 올리는 별도 축. Lv19,612에서 한
  레벨의 상대 기여가 0.076%라 후반 체감이 옅어지는데, 그 자리를 메우는 것이
  각성이다. 스탯 종류를 늘리는 일이라 이번 범위 밖.
- **실제 성장 가속** — `MONETIZATION_PLAN 9-5b`의 `base × 지수^((lv-1)^k)`, k<1.
  초반은 그대로 두고 후반만 싸져 200일 벽(잉여 1,247,620M)을 겨눈다. 사장님이
  실플레이로 체감한 뒤 결정.
- **혈액이 여전히 DPS에 비례** — `blood_per_sec`가 kill_time을 쓰므로 공격력이
  간접적으로 수급을 올린다. 완전 분리(구간만 보는 고정 배급)는 수입 곡선 교체라
  재측정이 강제되므로 뺐다.
