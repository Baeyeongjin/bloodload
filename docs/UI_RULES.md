# UI 규칙 — 여백 · 정렬 · 크기

> 마지막 업데이트: 2026-08-03

**UI를 만지기 전에 이 파일을 먼저 읽는다.** 도구(Claude/Codex)나 PC가 바뀌어도
같은 규칙이 적용되도록 여기 하나에 모은다.

이 규칙들은 전부 **실제로 깨진 화면을 고치면서** 나온 것이다. 각 항목에 "안 지키면
무슨 일이 생기는지"를 적어 뒀다 — 그게 규칙의 존재 이유다.

---

## 0. 제1원칙 — 정렬은 **재서** 맞춘다, 눈으로 맞추지 않는다

```bash
godot --path . --rendering-method gl_compatibility --resolution 576x896 \
      -- --autoshot --tab=growth
python tools/measure_text.py
```

`tools/measure_text.py` 가 스크린샷에서 **글자 잉크의 중심과 칸 중심의 차이**를 픽셀로
찍어 준다. ±1px 안이면 맞은 것이다.

> 눈으로 "조금 위 같다"고 `TEXT_NUDGE = 3` 을 넣었다가 **반대로 아래로 넘쳤다.**
> 그리고 진짜 원인(버튼 그림의 아래 8px이 알약이 아니었음)은 그 보정값에 가려
> 한참 뒤에야 찾았다. **눈대중 보정은 원인을 덮는다.**

같은 이유로 배경 지면 높이는 `tools/measure_ground.py` 로 잰다.

## 1. 좌표 — 16px 격자로 반올림하지 않는다

| 함수 | 쓰는 곳 |
|---|---|
| `Grid.px` / `Grid.pxv` | **UI 배치 전부.** 정수 픽셀로만 맞춘다 |
| `Grid.snap` / `Grid.snapv` | 배경·큰 덩어리처럼 16px 격자에 맞아야 하는 것만 |
| `Grid.u(n)` / `Grid.uv(x,y)` | 유닛(16px) → 픽셀 환산. 값 만들 때만 쓰고 반올림은 안 함 |

**안 지키면**: `snapv` 는 위치를 최대 8px 옮긴다. 그런데 `Label` 은 안 거치므로
버튼·아이콘만 밀리고 글자는 안 밀려 **서로 어긋난다.** 실제로 이것 때문에
"UI가 전체적으로 안 맞는다"가 계속 나왔다.

```
배수 버튼 pos   의도 (24.0, 9.6)  ->  snapv 결과 (32, 16)   어긋남 (+8.0, +6.4)
```

도트가 흐려지는 건 **소수점 좌표** 때문이지 16px 격자를 벗어나서가 아니다.

## 2. 여백 — 상수 하나만 본다

| 상수 | 값 | 뜻 |
|---|---|---|
| `Main.PAD` | 26 | 창 안쪽 여백 (좌·우·위·아래 공통) |
| `Main.CONTENT_W` | 524 | `PANEL_W - PAD*2` |
| `Main.CONTENT_BOTTOM` | 294 | `PANEL_H - PAD` |
| `Ui.PANEL_MARGIN` | 12 | 패널 그림의 테두리 두께 |
| `Main.TOP_PAD` | 24 | 상단 상태창 안쪽 여백 |

**`PAD` 는 `PANEL_MARGIN`(12)보다 확실히 커야 한다.** 테두리 두께만큼만 띄우면
글자가 테두리 무늬에 얹혀 안 읽힌다.

**세로 배치는 위에서부터 더해서 `CONTENT_BOTTOM` 을 넘는지 확인한다.**
예) 성장 창: `26 + 40(배수탭) + 16 + 3×60(행) + 8 + 18(요약) = 288` → `CONTENT_BOTTOM`(294) 안.

**마지막 요소는 창 바닥이 아니라 앞 요소의 끝을 기준으로 놓는다.**
`CONTENT_BOTTOM - 18` 처럼 바닥에 붙여 두면 행 높이를 바꾸는 순간 겹친다.

**안 지키면**: 마지막 줄이 창 밖으로 나가 탭바와 겹친다. 도감을 5칸×5줄로 짰다가
마지막 줄이 탭 아이콘 위에 찍혔다.

## 3. 글자 크기 — 칸이 좁으면 크기부터 내린다

| 상수 | 값 | 쓰는 곳 |
|---|---|---|
| `Type.SIZE_TITLE` | 33 | 제목 |
| `Type.SIZE_BODY` | 22 | 본문·큰 버튼 |
| `Type.SIZE_MID` | 16 | 폭이 정해진 버튼 |
| `Type.SIZE_SMALL` | 11 | 보조 정보 |

폰트가 **11×11 도트**라 11의 배수(11/22/33)가 가장 또렷하다. `SIZE_MID`(16)는
배수가 아니라 살짝 흐리지만, 칸에 안 들어가는 것보다 낫다.

**이 폰트는 한글 글자 폭이 글자 크기보다 넓다.** 152px 칸에 `강화 1.5만`(한글 6자)을
`SIZE_MID` 로 넣으면 잘린다 → `SIZE_SMALL` 로 내린다.

**여백과 글자는 같은 폭을 나눠 쓴다.** 둘 다 넉넉할 수는 없다.

## 4. 정렬

**버튼 안 글자** — `Ui.button()` 이 알아서 한다. 손대지 말 것.
- 가로: `alignment = CENTER`
- 세로: 스타일박스의 `content_margin_top == bottom` 이어야 가운데로 온다.
  한쪽만 키우면 그만큼 밀린다(`Ui.TEXT_NUDGE`, 지금은 0).
- `clip_text = true` — 넘치면 버튼을 밀지 않고 잘라낸다.

**아이콘 옆 글자** — `_panel_label(..., width, height)` 에 **높이를 준다.**
그 높이 안에서 세로 중앙정렬된다.

> **`clip_text` 를 켤 때는 반드시 폭을 같이 준다.** 폭 없이 켜면 폭이 0으로 잡혀
> **글자가 통째로 사라진다.** 실제로 스탯 행 글자가 전부 안 보인 적이 있다.

**여러 칸을 늘어놓을 때** — 화면 폭 한가운데에 놓는다.
```gdscript
const SLOT_X0 := (576.0 - (SLOT_GAP * 2.0 + SLOT_BOX)) * 0.5
```
왼쪽부터 쌓으면 오른쪽만 넓게 비어 **치우쳐 보인다.**

**격자** — 남은 폭을 칸 수로 나누고 각 칸의 **가운데**에 놓는다. 유닛으로 눈대중하면
마지막 칸이 테두리에 붙는다.

## 5. 9-slice — 그림에서 **쓸 영역만** 잘라 쓴다

생성된 도트 자산은 캔버스 안에 그림이 꽉 차 있지 않다. 그대로 늘리면 **투명 여백이나
엉뚱한 부분까지 늘어난다.**

| 자산 | 캔버스 | 실제 쓸 영역 | 안 잘랐을 때 |
|---|---|---|---|
| `btn.png` | 96×32 | `Rect2(26, 0, 44, 24)` | 좌우 투명 여백이 늘어 버튼이 쪼그라들고, **아래 8px 받침 때문에 글자가 4px 아래로** 쏠린다 |
| `bar_frame.png` | 128×32 | `Rect2(0, 3, 128, 26)` | 위아래 투명 여백만큼 테두리가 실선으로 붕괴 |

**무늬가 있는 가운데는 늘리면 번진다.** 그렇다고 `AXIS_STRETCH_MODE_TILE` 로 반복하면
조각 경계가 세로줄로 드러난다 — 둘 다 해 보고 **가운데가 균일한 색일 때만 늘린다**로
정리했다(무늬는 좌우 끝 캡에만 두면 늘어나지 않는다).

**세로는 원본의 정수 배로 그린다.** `bar_frame` 실제 그림 26px → **52px(2배)**.
1.4배 같은 걸 쓰면 어떤 도트 줄은 1px, 어떤 줄은 2px가 되어 지저분해진다.

## 6. 스프라이트 — 상자 안에 넣을 때

아이템 아이콘 원본이 **32/40/48/64/80/96px 로 제각각**이다.

```gdscript
Ui.icon(path, pos, box)   # box 안에 KEEP_ASPECT_CENTERED 로 맞춘다
```

**틀 안에 넣을 때는 틀의 안쪽 구멍보다 작게.** 80px 틀에 64px 상자를 쓰면
큰 무기가 틀 밖으로 삐져나온다 → `SLOT_ICON = 48`.

**세로로 줄 세울 때는 그림의 아래끝을 맞춘다.** 몹 그림은 32×32 안에서 차지하는
위치가 제각각이라(박쥐는 위, 슬라임은 아래) 가운데 정렬하면 **글자와의 간격이
칸마다 달라 보인다.** `Image.get_used_rect()` 로 실제 그림 범위를 재서 내린다
(`Main._sprite_drop`).

## 7. 화면 구획 (576 × 896)

| 영역 | y | 상수 |
|---|---|---|
| 상단 상태창 | 0 ~ 192 | — |
| 전투 띠 (보이는 부분) | 192 ~ 480 | `VIEW_TOP`, `VIEW_BOTTOM` |
| 하단 UI | 480 ~ 896 | `PANEL_AT`, `PANEL_SIZE` |

셋이 화면을 **빈틈없이** 덮는다. 검은 자리가 남으면 안 된다.

상단 마지막 줄은 **y 180을 넘으면 안 된다** — 패널 테두리(12px)에 물려 아이콘이 잘린다.

**배경은 아래를 기준으로 붙인다.** 배경 세로는 320(원본 160×2)이라 띠(288)보다 크다.
`VIEW_BOTTOM - 320` 에 놓고 넘치는 위쪽은 상단 패널이 가린다.

> 위를 기준(`VIEW_TOP`)으로 붙이면 **상단 패널을 키울 때마다 지면이 같이 내려가
> 바닥이 잘린다.** 상단 UI 높이를 조절하려면 이 규칙이 먼저 서 있어야 한다.

전투 띠 안의 지면선은 `ground_y` 이고 **막마다 다르다**(배경 그림의 바닥 높이가
다르기 때문). 상수로 두면 캐릭터가 공중에 뜬다.

## 8. 레퍼런스 기반 시각 계층

> 2026-08-03 사용자가 제공한 수집형 RPG 장비함·하단 메뉴 레퍼런스에서 확정.

**깔끔함이 장식보다 먼저다.** 한 덩어리는 한 역할만 맡고, 서로 다른 역할은 선·여백·
별도 판으로 분리한다.

- 콘텐츠 패널은 `y=480~800`, 하단 탭바는 `y=800~896`의 **독립 프레임**이다.
  한 장의 패널로 둘을 같이 덮지 않는다. 탭바 위쪽에는 분명한 분리턱이 있어야 한다.
- 장비 상세는 **왼쪽 큰 장비 전시 / 오른쪽 효과 / 아래 3×2 재화 정보 / 맨 아래 행동**
  순으로 읽힌다. 긴 설명 한 줄에 수치를 전부 넣지 않는다.
- 비용과 재료는 고정된 정보칸에 표시하고 버튼에는 `장착/Lv업/합성/분해/닫기`처럼
  행동만 짧게 쓴다.
- 보관함과 상세 화면은 등급별 배경·테두리색만으로 구분한다. 반복 반짝임은 쓰지 않는다.
- 반짝임은 보상을 강조해야 하는 **소환 결과에서만**, 희귀 이상에 사용한다.
- 상세 팝업은 화면 전체를 검게 덮지 않는다. 뒤 화면의 맥락을 남기고 팝업 프레임 자체로
  영역을 구분한다.
- 하단 메뉴는 아이콘을 같은 간격으로 놓고 선택 상태만 밝게 한다. 반복 장식이 아이콘보다
  먼저 보이면 자산을 다시 만든다.

새 UI를 만들기 전 이 절과 `PLAN.md`의 PixelLab 프롬프트 규칙을 함께 확인한다.

### 공용 테두리와 하단 탭바

- 공용 창은 최초 원화 `panel.png`를 `Ui.panel()` 9-slice로 늘려 각 영역을 끝까지 채운다.
  내부의 저대비 석재 무늬를 유지하고 별도 색 보정이나 생성형 외곽선을 겹치지 않는다.
- 장비 카드·장비 상세처럼 전용 PixelLab 프레임이 있는 화면에는 공용 모서리를 겹쳐
  올리지 않는다. 한 UI에는 한 종류의 외곽선만 보이게 한다.
- 하단 탭바는 큰 공용 패널을 늘리지 않는다. `tab_cell.png` 한 칸을 정확히 2배로 네 번
  반복해 576px을 채우고, 선택 칸만 밝게 보여 남는 폭과 이중 테두리를 막는다.
- 하단 글씨는 각 칸의 `y=54~78`에 두고 가로·세로 중앙 정렬한다. 전체 칸의 아래쪽 정렬을
  쓰면 붉은 선택선에 붙어 보이므로 사용하지 않는다.
- 소환 반짝임 Tween은 카드가 SceneTree에 들어간 뒤 만든다. 알파 `0→1→0`, 크기
  `0.25→1.3→0.25`로 반복해 정지 별 장식처럼 보이지 않게 한다.

## 9. 체크리스트 — UI를 고친 뒤

1. `godot --headless --path . --import` — 파스 에러 없나
2. 네 탭 각각 렌더해서 눈으로 확인 (`--tab=growth|gear|summon|codex`)
3. 글자가 칸을 넘거나 잘리지 않았나
4. 세로 배치 합계가 `CONTENT_BOTTOM` 안인가
5. `python tools/measure_text.py` — 어긋남 ±1px 안인가
6. `godot --headless --path . --script tests/BalanceTest.gd` / `tests/GearTest.gd`

> **알려진 문제**: `--tab=` 플래그가 가끔 요청과 다른 탭을 띄운다. 원인 미확인.
> 창별로 따로 렌더해서 확인할 것.
