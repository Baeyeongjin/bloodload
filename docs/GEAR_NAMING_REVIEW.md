# 장비 이름·아이콘 검수

## 2026-09-09 현재 적용 — 원본 그림에 맞춰 이름만 수정

사용자가 원본 이미지 복원 후, 장비 그림에 맞는 이름을 요청했다. 아래 2026-09-08의
아이콘 교체는 **취소된 과거 기록**이다. 현재는 72종 원본 그림을 기준으로 이름만
맞췄으며 이미지 파일·경로·ID·등급·배열 순서·무기 특성·강화 수치·가격은 유지한다.

대표 수정: 태양 언월도 → 태양 석궁, 황금 전투도끼 → 태양의 황금 가면,
장미 칼날 → 청록 혼등, 청명검 → 해골 지팡이, 사냥꾼 코트 → 사냥꾼 망토.
원본부터 무기 슬롯에 망토 그림 등이 연결된 경우에도 그림과 슬롯을 재배치하지 않고
실제 보이는 물건의 이름을 사용한다. 저장된 아이템은 기존 `normalize_catalog_item()`
호출을 통해 불러올 때 새 표시 이름을 받는다. 저장 형식을 추가하지 않았다.

`tests/GearNameCheck.gd`로 72개 이름/ID 고유성, 6등급×4개 구성, 원본 아이콘 존재,
기존 이름 갱신 시 레벨·기본 수치·특성 보존, 원본 도트 폰트를 확인했다.

# 2026-09-08 과거 작업 — 아래 아이콘 교체는 원복됨

대상은 `GearDefs.CATALOG`의 무기 24종·방어구 24종·장신구 24종, 총 72종이다.
72개 ID와 표시 이름은 모두 고유하다. 하위 등급의 재료·용도 이름에서 상위 등급의
핏빛·망령·심연·시조 이름으로 이어지는 흐름은 유지한다. 단순한 일반 장비 이름까지
모두 고유명사로 바꾸지는 않았다.

이후 사용자 승인 범위에서 **아이콘 불일치 28건과 추가 검토 3건, 총 31개 PNG를 교체했다**.
새 이미지 생성 없이 기존 도트 원본을 재사용하고 필요한 색·장식·연결부를 직접 정리했다.
ID나 아이콘 경로 대신 `assets/items/<동일 ID>.png`의 내용만 교체했다.
[교체 전 72종 전수판](../build/qa/gear-naming/catalog-art.png)과
[교체 후 전수판](../build/qa/gear-naming/catalog-after.png)은 왼쪽부터 무기 4열,
방어구 4열, 장신구 4열이며 위에서 아래로 일반→신화다.
[나란히 전후 비교](../build/qa/gear-naming/catalog-before-after.png)도 저장했다.

## 아이콘 교체 방식

- 원본 재사용: 석궁·부메랑·푸른 검·룬 망치·관 모양 검·녹색 낫·물약·성배·십자가·
  왕관·보주·책·가면·날개 등은 이미 있던 실제 물건 형태의 아이콘을 사용했다.
- 작은 색 교정: 철 망치, 비취 표창, 장미 칼날, 망령 낫, 황금 도끼는 기존 형태를
  유지하고 해당 재질·이름에 맞는 색만 정리했다.
- 직접 도트 정리: 독사 단장의 머리, 태양 언월도의 칼날, 혼등 지팡이의 손잡이와
  랜턴 연결, 반지의 해골 장식은 기존 원본 부품과 32px 좌표 편집으로 완성했다.
- 모든 교체본은 **32×32 RGBA, 알파 0/255**이며 투명 픽셀의 RGB도 0이다.
  흰 체크무늬나 사각 배경을 투명도로 간주하지 않았다.
- 한 교체 대상이 다른 아이콘의 원본이 되므로 입력을 먼저 모두 읽고 교체했다.
  재실행할 때도 백업을 우선 읽어 이미 교체된 그림을 잘못 재사용하지 않는다.
- [31개 원본 매핑](../build/qa/gear-naming/icon-replacements.json),
  [적용 도구](../build/qa/gear-naming/restore-icons.cjs),
  [백업 해시·알파·크기 검증](../build/qa/gear-naming/icon-validation.json).

## 효과·표시 경로와 남은 범위

- 개별 장비의 독립적인 배경 설명은 `CATALOG`에 없다. 무기 특성은 등급 내 배열 위치에
  따른 `WEAPON_TRAIT` 4종이며, 설명 원천은 같은 파일의 `TRAIT_TEXT`다.
- `stun` 설명의 ‘얼어붙는다’는 냉기 공격으로 읽힐 수 있다. 실제 기절을 분명히 하려면
  ‘맞은 적을 잠시 기절시킨다’가 더 정확하다. 이번에는 장비 표시명 범위에 맞춰 유지했다.
- 보관함·도감 목록은 `GearDefs.items_of()`를 읽고 상세 화면은 `item["name"]`을 표시한다.
  새 아이템 생성·승급도 카탈로그 이름을 사용한다. 재련 기능은 사용자 요청으로 제거했다.
- 기존 저장본은 `Main.gd`의 인벤토리·장착 장비 로드에서 각각
  `GearDefs.normalize_catalog_item()`을 거쳐 같은 ID의 최신 이름을 받는다.
  이름 때문에 아이템이 새 ID로 바뀌거나 수량·강화가 초기화되는 변경은 하지 않았다.
- 별도 이름 원천: 펫 장비 25종은 `PetDefs.gd`의 `GEAR`, 유물은 `RelicDefs.gd`,
  의상은 `SkinDefs.gd`다. 이번 72종 감사의 수정 범위에는 포함하지 않았다.
  장신구와 유물의 ‘황금 가면’은 서로 다른 시스템의 이름 중복이다.
- 후속으로 펫 장비 25종 이름도 읽었다. 확실한 오탈자는 발견하지 않아 `PetDefs.gd`는
  수정하지 않았다. 펫 장비 아이콘 전체를 이번 31개 교체 범위에 포함한 것은 아니다.

## 검증

- 변경 전후 전체 파일 비교: 표시 문자열 8개 외 변경 없음.
- 72개 ID와 배열 순서 동일, 표시 이름 72개 중복 없음.
- 기존 정규화·상세 이름 조회 경로 유지 확인.
- 교체 아이콘 31개: 원본 백업 존재·스테이징과 실제 PNG 일치·32×32·이진 알파·
  투명 픽셀 RGB 0 검사 통과. 각 파일의 변경 전후 SHA-256 기록.
- 표시명 수정 후 `tests/GearTest.gd`: **exit 0 / GearTest OK**.
  `APPDATA`와 `LOCALAPPDATA` 모두 `build/qa/gear-naming/profile-*`로 격리했다.
- 로그: [GearTest.log](../build/qa/gear-naming/GearTest.log).
  기존 Windows root certificate store 경고가 있으나 assertion 실패는 없다.
- 31개 아이콘 적용·root의 재임포트 후 같은 검사를 한 번 재실행:
  **exit 0 / GearTest OK**. 양쪽 프로필을 다시 격리했으며
  [GearTest-icons.log](../build/qa/gear-naming/GearTest-icons.log)에 기록했다.

전후 전수판을 직접 확인했다. 위 검증은 이름 조회·자산 형식·기존 장비 규칙을 확인하며,
실제 장비 화면에서의 전체 사용성 평가는 별도다.
