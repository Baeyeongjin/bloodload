## 3. 완료 — 겹침 (2026-08-05). **칸 좌표는 안 건드렸다**

칸을 옮기러 갔다가 **자가 틀린 것을 먼저 찾았다.** `--gaps` 가 상자 폭
(`_size()*0.5`)으로 재는데 32px 캔버스에 잉크가 26px 만 차 있어 한쪽당 6px 씩
과장됐다. 그 수치로 칸을 옮겼으면 과보정이다.

| | 예전 문서 | 잉크로 실측 |
|---|---|---|
| `LANES[0]` 부족분 | 22px | **12px** |
| 정지 상태 최악 겹침 | -4.4 (지표 오차라 적혀 있었다) | **-15.3 (실재했다)** |

> **이 절의 "상자를 쓰니 표적과는 안 겹친다"는 그 뒤에 뒤집혔다.** 안 겹치는
> 대가가 곧 빈 거리였다 — 아래 3-1 을 먼저 읽는다.

**원인도 칸 간격이 아니었다.** `_strike_spot` 은 이미 상자+`BODY_HALF`(78)를 쓰므로
표적일 때는 안 겹친다. 겹치는 건 `_tick_hero_attack` 이 **스킬 시전 중
(`SKILL_DUR` 0.70초) 통째로 return** 해서 표적을 다시 안 잡는 동안, 영웅이 대기
자리에 굳은 채 큰 몹이 옆 칸에 도착하는 경우였다.

`_clear_idle()` 이 표적 없을 때도 몹 몸통 밖으로 민다. 3-1 30초 측정:

```
이전  36건 (정지 27 / 대시중 9)   정지 최악 -15.3
이후  22건 (정지 16 / 대시중 6)   도착한 몹과의 정지 겹침 최악 -8.5
```

칸 좌표를 안 건드렸으므로 `APPROACH_SECONDS` 와 오프라인 판정은 그대로다.

### 남은 것

- **도착한 몹과의 -8.5 는 버그가 아니라 1차원 절충이다.** 셋(`_strike_spot` ·
  `_stand_ok` · `_can_hit_foe`)은 이미 같은 값을 보고 `BODY_HALF` 를 바닥으로 깐다
  — 표적과는 구조적으로 안 겹친다. 겹치는 건 **표적이 아닌 몹**이고,
  `_clear_spot` 이 밖으로 밀려다 "표적에게 못 닿는 자리"라 포기한 경우다.
  억지로 밀면 공격이 통째로 멈추는 버그가 재발한다(주석에 이력 있음).

> **설 자리 창은 구조적으로 좁고, 넓힐 수 없다.**
> `[BODY_HALF − STAND_TOL, max(사거리, BODY_HALF) + 1]` = **[24, 31], 7px.**
>
> 사거리를 올려서 넓히려 했는데 **안 된다.** 32px 캔버스에서 사거리 상한은 32이고
> (`(32/2 − 잉크왼끝) × 2`, 잉크가 x=0 에 닿아야 32), attack 26 · heavy 18 은 둘 다
> `BODY_HALF 30` 에 눌려 `max(사거리, 30) = 30` 으로 **이미 같은 값**이다.
> 사거리를 30 → 32 로 올려도 창은 **2px** 넓어질 뿐이다. 생성비를 쓸 값이 아니다.
> (2026-08-05 실측 정정 — 처음엔 "30 초과로 뽑으면 겹침이 준다"고 적었는데 틀렸다.)
>
> 창을 정말 넓히려면 `BODY_HALF`(30, 영웅 잉크 실측)를 줄여야 하는데 그건 그림이다.
> **남은 -8.5 는 받아들이는 게 맞다.**
- **걸어 들어오는 중인 몹이 영웅을 지나가는 것**(-20~-40)은 1차원 화면에서
  못 없앤다. 손대지 않는다.
- 칸을 정말 밖으로 밀 일이 생기면 **`APPROACH_SECONDS 0.55` 를 다시 잰다** —
  `Balance.stage_seconds()` 를 통해 오프라인 판정까지 흔든다.

## 3-1. 완료 — 설 자리를 상자에서 잉크로 (2026-08-05, 위를 정정한다)

사장님: "뭔가 멀리서 싸우는 느낌이라 이질감 있음." 느낌이 아니라 실측이 맞았다.

```
보스전, 둘 다 정지 상태의 빈 거리
  이전   뜸 19.6 ~ 28.0  (계속)
  이후   뜸 0건
```

**설 자리를 상자(`_size()*0.5`)로 잡고 있었다.** 보스 캔버스는 64px 인데 잉크는
44~50px 뿐이라 한쪽당 20~28px 이 빈 공간이고, 영웅이 그만큼 떨어져 허공을 쳤다.
3장에서 "상자를 쓰니 표적과는 구조적으로 안 겹친다"고 넘어간 바로 그 성질이,
화면에서는 이 빈 거리로 나타난 것이다. **겹침만 보고 뜸을 안 봤다.**

`_strike_spot` · `_stand_ok` · `_foe_gap` · `_clear_spot` **넷을 같이** 잉크로 바꿨다.
하나만 바꾸면 닿지 않는 자리에 서게 된다 — 셋(넷)이 같은 값을 봐야 한다는 규칙은
그대로고, 보는 값만 상자에서 잉크로 옮겼다. 테스트 5종 통과.

`body_half()` 는 **가장 넓은 프레임으로 고정해 캐시한다.** 프레임마다 재면 잉크 폭이
19.6~28.0 으로 오르내려서 영웅이 몹 숨쉬는 대로 앞뒤로 흔들린다.

### 자가 한쪽으로만 열려 있었다

`--gaps` 가 **겹침(음수)만** 찍고 있었다. 겹침을 없애고 나니 반대쪽 고장이 남았는데
지표에는 안 보였다 — 아침에 "남은 -8.5 는 받아들인다"로 닫을 수 있었던 이유가
그것이다. 이제 `GAP_MAX(8.0)` 을 넘는 **뜸**도 찍는다.

뜸은 **지금 상대하는 몹만** 찍는다(`_strike_spot` 이 그 몹을 가리킬 때). 다른 칸
몹과는 원래 멀어서, 같이 찍으면 진짜 문제가 잡음에 묻힌다.

## 3-3. 저장본을 날렸다 (2026-08-05) — 다음 사람 주의

덮어썼다. 로그에 에러는 안 남는다 — **조용히 날아간다.**

- 실행 중인 Godot 을 끌 때 `Godot*` 로 싸잡아 죽이면 **사장님 에디터까지 죽는다.**
  실제로 그렇게 했다. 내가 띄운 PID 만 골라 끈다.

> **한 줄(오른쪽만)로 바꿔 봤다가 되돌렸다** — 겹침은 사라졌지만 몹이 한 마리씩

## 3-4. 순차 교전 전환 (2026-08-06) — 3장의 절충들을 구조로 해소

사장님이 레퍼런스 방치형에서 본 리듬으로 전투를 바꿨다: **영웅과 서로 때리는
몹은 언제나 한 마리다.** 나머지는 제 칸에서 기다리고(공격 금지), 교전 몹이 죽는
걸 보고 나서 다음이 줄에서 걸어 나온다. 교전 몹은 영웅 앞 잉크 간격까지 걸어오고
영웅도 마주 달려 만난다. 칸이 다 차면 스폰을 미룬다 — 다음 놈은 화면 밖에서
기다리다 줄이 당겨지면 걸어 들어온다.

- `Foe.engaged` 게이트 — 교전 몹만 휘두른다. **쿨다운도 같이 멈춘다**: 기다리는
  동안 돌려 두면 교전 순간 밀린 쿨다운이 음수로 쌓여 연타가 터진다
- `Main._tick_engage` — 교전 선정(도착한 몹 중 최근접) + 교전 몹 자리 추적.
  예고(`telling`)·스윙(`swinging`) 중에는 자리를 안 옮긴다. 죽는 중에는 다음을
  안 부른다 — 그 서는 박자가 "처치했다"를 읽게 한다
- `_reflow_side` — 빈 칸을 앞에서부터 당겨 세운다. 순서를 보존해야 몹끼리 안 지나친다
- `_refill_lanes` — 한쪽 3칸이 차면 스폰 자체를 미룬다 (화면 밖 대기)
- 오프라인 동시 타격 수 = **1 고정** (`FOES_IN_REACH` 삭제)

**3장에서 "받아들인다"고 접었던 두 잔여가 구조적으로 사라졌다** — 표적 아닌 몹이
영웅 곁에 설 일도, 걸어 들어오며 영웅을 통과할 일도 없다. `--gaps` 25초:

```
전환 전  16건, 최악 -49.9 (통과 겹침 다수)
전환 후   5건, 최악  -9.8 (전부 첫 칸 기하 — 3장 실측의 그 12px)
```

> **"한 줄로 바꿨다 되돌렸다"(3-3 끝의 상자)와 다르다.** 그때는 스폰을 한 방향으로
> 줄였다가 정적이어서 되돌렸다. 이번엔 **양방향 스폰·영웅의 좌우 이동은 그대로**고
> 교전만 직렬화했다 — 사장님이 레퍼런스에서 확인한 조합이다("전혀 지루하지 않은
> 느낌"). 화려한 전투 모션이 지루함을 막는 축이므로 모션 쪽 투자가 유효하다.

CombatRulesTest 에 교전 게이트 검사(기다리는 몹은 코앞이어도 안 휘두르고, 교전
몹은 휘두른다)를 넣었다. 기존 보스·사거리 probe 는 `engaged = true` 를 켜 줘야
한다 — 실전에서 보스는 혼자라 늘 교전 상태다.

## 4. 완료 — 보스 특수 패턴 모션 5종 (2026-08-05)

틀은 `Foe.gd` 에 있다. 보스·중간보스만, 세 번째 스윙마다 멈춰서 발밑에 착탄
범위를 그리고 넓게 친다:

```
SPECIAL_EVERY  3      몇 번째 스윙마다
SPECIAL_TELL   0.85   멈춰서 예고하는 시간
SPECIAL_REACH  1.7    착탄 범위 배수 — 발밑에 그리는 판이 곧 이 값
SPECIAL_DMG    2.4    피해 배수. 예고 밖으로 대시하면 통째로 빗나간다
```

예고는 원이 아니라 **바닥에 누운 판**이다(`_draw_attack_tell`). 옆에서 보는
화면이라 눌린 원은 공중에 뜬 고리로 보인다.

보스 5종에 패턴별 전용 **9프레임** 모션이 붙었다(`assets/anim/boss_N_special/`).
`Foe._special_frames` 를 `{anim_key}_special` 에서 읽고 `_draw` 가 `special_swing`
일 때 그걸 쓴다. **없으면 평타로 조용히 떨어진다** — 그래서 `CombatRulesTest` 가
5종 45프레임을 검사한다.

| 막 | 보스 | 패턴 | 프레임에 들어간 것 |
|---|---|---|---|
| 1 | 망령 기사 | 내려찍기 | 무기를 들었다 내려찍음 |
| 2 | 가고일 군주 | 3연타 장판 | 발밑 충격파 (f4~f6) |
| 3 | 프로스트 골렘 | 서리 장판 | 얼음 가시가 솟음 (f4~f6) |
| 4 | 눈알 덩어리 | 소환 | 촉수가 벌어졌다 오므라듦 |
| 5 | 다크 나이트 | 돌진 | 검을 옆으로 뻗고 전진 (f6~f8) |

**중간보스는 내려찍기만** (사장님 결정), 전용 모션 없이 평타로 떨어진다.
잡몹은 특수 패턴 없음 — 여섯이 동시에 예고하면 바닥이 덮여 전투가 안 보인다.

오프라인 피해 모델도 같이 고쳤다. `_offline_profile` 의 `damage` 가 평타 기준이라
패턴이 붙으면 오프라인은 "깼다"는데 실제로 돌리면 죽는다.
`Foe.avg_attack_mult()` 가 `(평타 2 + 특수 1) / 3 = 1.47` 배를 곱한다.

## 5. 이번 세션에서 배운 것 — 같은 부류의 버그가 세 번 났다

**"영웅이 설 자리 / 휘두를 조건 / 피해가 닿을 조건"이 서로 다른 값을 보면**
만족하는 거리가 아예 없어지거나 몹 안에 서게 된다. 화면에서는 "겹쳐 보이네" 나
"공격이 느리네" 로만 보여서 원인을 못 찾는다.

지금은 셋 다 `BODY_HALF`(30, 실측) 를 바닥으로 깔고 `CombatRulesTest` 가 갈리는지
검사한다. **이 셋 중 하나를 고칠 때는 반드시 나머지 둘을 같이 본다.**

같은 이유로 **그림을 다시 뽑으면 사거리가 조용히 바뀐다.** `_motion_reach` 는
불투명 픽셀에서 재므로 포즈가 바뀌면 값이 바뀐다. 검사에 숫자를 박아 뒀으니
그림을 바꾸면 거기서 먼저 걸린다(지금 attack **26**, heavy 18).

또 하나: **`Ui.icon` 은 `expand_mode` 를 맨 먼저 줘야 한다.**
`Control.update_minimum_size()` 가 트리 밖 노드에서 그냥 되돌아가서, `position` 을
먼저 주면 최소 크기 32 가 캐시되고 이후 변경이 안 먹는다 — 12 를 넣어도 32 로
그려졌다. `GearTest` 에 회귀 검사가 있다.

## 6. 개발 플래그

```bash
godot --path . --rendering-method gl_compatibility --resolution 576x896 -- --autoshot --wait=N
```

| 플래그 | 하는 일 |
|---|---|
| `--gaps` | 영웅과 몹이 겹치는 순간만 골라 찍는다 (겹침·자리 문제 진단) |
| `--reward` | 보상 창을 띄운 채로 캡처 (F9·가이드 수령으로만 떠서 캡처가 안 됐다) |
| `--chest` | 방치 보상 상자 |
| `--stage=3-1` | 그 구간에서 시작 |
| `--tab=growth\|gear\|summon\|codex` | 그 창을 연 채로 |
| `--skills[=N]` / `--skillfx[=형태]` / `--pull=gear:10` | 스킬·소환 화면 |

**렌더는 반드시 격리한다** — `$env:APPDATA` 를 임시 폴더로 바꾼다. 사장님 저장본으로
돌리면 창이 뜬 사이 버튼이 눌려 **실제로 장비가 분해된 사고**가 있었다.

## 7. 검증

```powershell
# PC 마다 다르다. 콘솔판이어야 stdout 이 잡힌다.

$GODOT = "C:/Users/user/Godot/Godot_v4.7-stable_win64_console.exe"
& $GODOT --headless --path . --import
Get-ChildItem tests/*.gd | ForEach-Object {
  $o = & $GODOT --headless --path . --script "tests/$($_.Name)" 2>&1 | Out-String
  if ($o -match "Assertion") { "FAIL $($_.Name)" } else { "OK $($_.Name)" }
}
```

**마지막 줄만 보면 안 된다.** `assert` 가 실패해도 실행이 이어져 `OK` 가 찍히고
종료 코드도 0 이다. 출력에서 `Assertion` 을 걸러 봐야 한다. 각 파일 앞에 20초
watchdog 이 있어 멈춰도 반드시 끝난다.

배경을 새로 뽑으면 `tools/fit_ground.py` → `tools/make_seamless.py` **순서대로**.
거꾸로 하면 이음매 스냅샷이 320줄로 굳어 세로 자르기가 되돌려진다.
